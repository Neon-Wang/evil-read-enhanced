# Zotero Relay

## Purpose

Use this skill to make a fresh computer reproduce the EvilRead execution workspace:

- clone or update `evilread-workspace`
- sync Zotero mirror files before and after `start-my-day`
- use `git.jiashengfan.space` as the external Git endpoint
- keep Git transport encrypted and credentials encrypted or in the OS credential store, never in plaintext repo files

## Fixed Contract

- Local workspace path on Windows: `C:\GitClient\windows\repos\evilread-workspace`
- Local Git service expected on this machine: `https://127.0.0.1:18083`
- External hostname expected by other computers: `https://git.jiashengfan.space`
- Start My Day wrapper: `scripts/run-start-my-day.ps1`
- Relay sync wrapper: `scripts/sync-zotero-workspace.ps1`
- Credential envelope tool: `tools/relay_credentials.py`
- Local TLS relay tool: `tools/git_tls_relay.py`

## Security Contract

Do not assume Cloudflare Access on `git.jiashengfan.space`. Git client-to-server protection must be handled by Git over HTTPS plus credentialed access:

- local smoke tests use `https://127.0.0.1:18083/o2/evilread-workspace.git`
- production remotes use `https://git.jiashengfan.space/o2/evilread-workspace.git`
- credentials are passed to Git with an in-memory Basic Auth header from the encrypted envelope
- local HTTPS verification uses the generated CA/cert path from `git_ca_cert`
- never put tokens into remote URLs, notes, logs, screenshots, or committed files

## Credential Rule

Never commit plaintext credentials. Allowed files:

- `deploy/relay/credentials.example.json`: schema only
- encrypted credential envelope generated by `tools/relay_credentials.py`
- OS Git Credential Manager entries

Plain files such as `credentials.local.json`, `credentials.plain.json`, or copied token notes must stay local and ignored.

## First Machine Setup

1. Start the HTTPS relay to local Gitea:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start-git-tls-relay.ps1
   ```

2. Confirm the local Git endpoint is reachable:

   ```powershell
   Test-NetConnection 127.0.0.1 -Port 18083
   ```

3. Confirm the local HTTPS endpoint responds:

   ```powershell
   curl.exe -k https://127.0.0.1:18083/
   ```

4. Confirm the public hostname maps to this computer externally:

   ```powershell
   Invoke-WebRequest -UseBasicParsing https://git.jiashengfan.space/
   ```

5. Create a local plaintext credential file outside Git or under an ignored name:

   ```powershell
   Copy-Item deploy\relay\credentials.example.json deploy\relay\credentials.local.json
   notepad deploy\relay\credentials.local.json
   ```

6. Encrypt it:

   ```powershell
   $env:EVILREAD_RELAY_PASSPHRASE = "<strong-passphrase>"
   .\.venv\Scripts\python.exe tools\relay_credentials.py encrypt `
     --input deploy\relay\credentials.local.json `
     --output deploy\relay\credentials.enc.json
   ```

7. Delete the plaintext file after encryption:

   ```powershell
   Remove-Item deploy\relay\credentials.local.json
   ```

8. Verify credentialed local fetch before switching to the domain remote:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts\sync-zotero-workspace.ps1 `
     -Credentials deploy\relay\credentials.enc.json `
     -UseLocalRelay `
     -BeforeStartMyDay
   ```

9. After local fetch passes, switch the same envelope or environment remote back to `https://git.jiashengfan.space/o2/evilread-workspace.git`.

## New Computer Relay

1. Clone `evil-read-enhanced`.
2. Install dependencies:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\pip.exe install -r requirements.txt
   ```

3. Provide either `EVILREAD_WORKSPACE_REMOTE` or an encrypted credential envelope with `workspace_remote`, `git_username`, and `git_token`.
4. Pull the workspace mirror:

   ```powershell
   $env:EVILREAD_RELAY_PASSPHRASE = "<same-passphrase>"
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts\sync-zotero-workspace.ps1 `
     -Credentials deploy\relay\credentials.enc.json `
     -BeforeStartMyDay
   ```

5. Open `deploy/code-server/evilread.code-workspace` or run `start-my-day`.

## Start My Day Integration

Before production `start-my-day`, always sync:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\sync-zotero-workspace.ps1 `
  -Credentials deploy\relay\credentials.enc.json `
  -BeforeStartMyDay
```

Then run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\run-start-my-day.ps1
```

Afterward, verify Zotero closure:

```powershell
.\.venv\Scripts\python.exe tools\zotero_closure_audit.py
```

The run is not green unless these are all zero:

- `duplicate_title_groups`
- `zotero_parent_missing_mirror_json`
- `mirror_json_not_in_zotero_parent`
- `missing_original_attachment_for_mirrored_pdf`
- `missing_translated_attachment_for_mirrored_pdf`

## Recovery

- If pull fails because local workspace has changes, stop and inspect `git -C C:\GitClient\windows\repos\evilread-workspace status --short`.
- If encrypted credentials fail, do not print token values. Re-run decrypt with `--redacted`.
- If `git.jiashengfan.space` is down, test local `127.0.0.1:18083` on the host machine before changing remotes.
- If TLS verification fails during local testing, regenerate the relay cert/key locally and keep both files ignored.
- If Zotero native state diverges from mirror, run `tools/zotero_closure_audit.py` first, then use `tools/zotero_runjs_dedupe.py` or `tools/zotero_runjs_import_mirror_items.py` only for the reported class of mismatch.
